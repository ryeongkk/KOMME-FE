# components

## 목적

App Router 라우트 트리 바깥에서 여러 라우트가 공유하는 React 컴포넌트입니다.

## 하위 디렉토리

| 디렉토리 | 설명 |
|-----------|---------|
| `ui/` | 특정 기능에 속하지 않는 범용 재사용 프리미티브 (예: `bottom-sheet.tsx`, `text-field.tsx`, `tapbar.tsx`, `schedule-card.tsx`, `spot-card.tsx`, `visit-date-picker.tsx`) |
| `home/` | 홈 화면 전용 컴포넌트 (`home-screen.tsx` = `/`) |
| `course/` | 코스 탭 전용 컴포넌트 (`course-screen.tsx` = `/course`, Upcoming/History 세그먼트 탭 + 탭별 코스 카드 리스트/공유 빈 상태 + FAB; `course-detail-screen.tsx` = `/course/[id]`, 뒤로가기 헤더 + 스팟 타임라인; `course-create-screen.tsx` = `/course/create`, 코스 생성 1/3단계(장소 검색) + 전체화면 검색 모드) |
| `login/` | 로그인 플로우 화면 전용 컴포넌트 (`login-screen.tsx` = `/login`, `terms-screen.tsx` = `/login/terms`, `email-screen.tsx` = `/login/email`, `code-screen.tsx` = `/login/code`, `password-screen.tsx` = `/login/password`, `nickname-screen.tsx` = `/login/nickname`) |
| `my/` | 마이페이지 플로우 화면 전용 컴포넌트 (`my-screen.tsx` = `/my`, `my-account-screen.tsx` = `/my/account`(로그아웃 확인 다이얼로그 포함), `edit-profile-screen.tsx` = `/my/account/edit`(닉네임 변경), `delete-account-screen.tsx` = `/my/account/delete`(계정 탈퇴 동의 + 최종 확인 다이얼로그), `language-setting-screen.tsx` = `/my/language`, `terms-policy-list-screen.tsx` = `/my/terms`, `terms-policy-detail-screen.tsx` = `/my/terms/service`·`/my/terms/privacy`·`/my/terms/location` 3개 라우트가 공유하는 헤더 전용 컴포넌트) |

## AI 에이전트를 위한 안내

### 이 디렉토리에서 작업할 때
- 새 화면(라우트)이 생기면 그 화면 전용 컴포넌트는 `login/`처럼 화면 이름을 딴 하위 폴더에 넣으세요. 여러 화면에서 재사용되는 범용 UI 프리미티브(바텀시트, 모달, 버튼 등)만 `ui/`에 넣습니다. 어느 한 화면에서만 쓰는 컴포넌트를 `ui/`에 넣지 마세요 — 두 번째 사용처가 생길 때 옮기세요.
- `nickname-screen.tsx`의 닉네임 중복 확인은 아직 백엔드 API가 없어 예약어 배열(`RESERVED_NICKNAMES`)로 흉내만 낸 상태입니다 — 실제 중복 확인 엔드포인트가 생기면 그걸로 교체하세요.
- `ui/schedule-card.tsx`는 D-DAY 뱃지 + 코스명 + 날짜/스팟 개수 + Edit Schedule/View Course 버튼으로 된 코스 카드(Figma `card_schedule`)입니다. 원래 `home-screen.tsx`에 로컬로 있었는데 `course-screen.tsx`(`/course`)가 두 번째 사용처가 되면서 `ui/`로 옮겼습니다 — 두 화면 모두 `Schedule` 타입과 `ScheduleCard`를 가져다 씁니다. `Schedule`은 `id: string`을 필수로 가지며 View Course는 `Link href={`/course/${schedule.id}`}`로 연결되어 있습니다. Edit Schedule은 아직 `/course/[id]/edit` 라우트가 없어 정적 상태입니다.
- `ui/spot-card.tsx`는 이미지+지역+이름+저장수/거리+영업시간으로 된 스팟 카드입니다. 원래 `spot-list-screen.tsx`에 로컬로 있었는데 `course-detail-screen.tsx`(`/course/[id]`)가 두 번째 사용처가 되면서 `ui/`로 옮겼습니다 — `Spot` 타입(`spots/data.ts`)을 받아 `/spots/[id]`로 연결되는 `Link`입니다.
- `ui/visit-date-picker.tsx`(`VisitDatePicker`)는 날짜 바텀시트 필드입니다. 지금은 `course/create-spots-step.tsx` 한 곳에서만 쓰이지만(다른 `ui/*`처럼 "두 번째 사용처가 생기면 옮긴다" 대신 요청에 따라 처음부터 `ui/`에 둔 예외), 날짜 선택이 필요한 다른 화면이 생기면 바로 재사용할 수 있게 하려는 의도입니다. `value`/`onChange`(확정된 날짜)만 controlled props로 받고, 달력 커서/임시 선택 상태는 내부에 캡슐화합니다. `useId()`로 만든 고유 id를 트리거 버튼의 `popoverTarget`과 시트 `id`로 걸어 `ui/bottom-sheet.tsx`(`BottomSheet`)를 재사용합니다 — 이 컴포넌트는 원래 `title`이 필수였는데(`login-screen.tsx`의 언어 설정 시트), 캘린더 시트는 Figma상 타이틀 줄이 없어서 `title`을 optional로 바꿨습니다(안 주면 그 줄 자체가 렌더링 안 됨). 시트를 열 때(`onClick`, `popoverTarget`과 별개로 동작) 커서/임시 선택값을 `value ?? 오늘`로 리셋하고, Confirm 버튼이 `onChange`를 호출하면서 동시에 `popoverTargetAction="hide"`로 시트를 닫습니다 — 취소는 없고 바깥 탭(popover 기본 동작)으로만 닫을 수 있습니다. 인접 달 날짜는 회색으로 채워 넣지만 클릭은 막아둔 상태입니다(`ponytail` 코멘트) — 탭해서 달을 넘기는 동작이 필요해지면 그때 추가하세요.
- `course/course-screen.tsx`(`/course`)는 Upcoming/History 세그먼트 탭 상태를 `useState`가 아니라 URL 쿼리(`?tab=history`, 기본값 Upcoming은 쿼리 없음)로 관리합니다 — `useSearchParams`로 읽고, 탭 클릭 시 `router.replace`(뒤로가기 스택에 안 쌓임)로 씁니다. 코스 카드의 View Course로 `/course/[id]`에 들어갔다가 뒤로가기(`router.back()`)하면 브라우저 히스토리상 바로 이전 URL(`/course` 또는 `/course?tab=history`)로 돌아오므로 어느 탭에서 진입했는지가 자연스럽게 유지됩니다. `useSearchParams`를 쓰는 클라이언트 컴포넌트라 `src/app/course/page.tsx`에서 `<Suspense>`로 감싸야 정적 빌드가 됩니다(`login/code-screen.tsx`와 같은 패턴). 탭 밑줄은 Figma 구조(`flex-[1_0_0]`로 텍스트 영역을 늘려 2px 바가 탭 바닥에 붙는 방식)를 그대로 따라야 합니다 — 텍스트+바를 통째로 `justify-center`로 가운데 정렬하면 바가 바닥에서 떠서 디자인과 어긋납니다. Upcoming 탭(Figma 노드 `137:1121`/`354:7845`)은 `UPCOMING_COURSES`(정적 스텁 배열, 코스 API 없음)가 비어 있으면 `EmptyState`를, 있으면 `ScheduleCard` 리스트를 보여줍니다. History 탭(노드 `354:7785`/`354:7899`)은 `HISTORY_COURSES`가 비어 있으면 같은 `EmptyState`를, 있으면 로컬 `HistoryCard`(뱃지 없이 "View Course" 버튼 1개짜리 카드, `ScheduleCard`와 구조가 달라 별도 컴포넌트로 둠) 리스트를 보여줍니다 — `HistoryCard`의 View Course도 `/course/${course.id}`로 연결됩니다. 우하단 FAB(+, `PlusIcon`)는 `Link`로 `/course/create`에 연결됩니다. FAB는 데스크톱에서도 `max-w-sm` 중앙 정렬 폭을 벗어나지 않도록 `fixed inset-x-0 mx-auto max-w-sm` 래퍼 안에 둡니다 — `ui/bottom-sheet.tsx`가 쓰는 것과 같은 패턴입니다.
- `course/course-create-screen.tsx`(`/course/create`)는 코스 생성 플로우 1/3단계(Figma 노드 `324:3543`/`347:6408`)입니다. 헤더+진행바("1/3", `bg-gray-100` 트랙 위 `bg-primary` 채움, `(현재 단계/전체 단계)*100%` 너비) + 헤딩 + 장소 검색 필드(밑줄 스타일 버튼, 탭하면 검색 모드로 전환) + Use current location 버튼(geolocation API 없어 `location`을 그냥 "Current Location" 문자열로 세팅하는 스텁) + 하단 Next 버튼(장소를 고르기 전엔 비활성, 2/3 라우트가 없어 `onClick` 미연결)으로 구성됩니다. 검색 모드(내부 `searching` state, 별도 라우트 아님 — 뒤로가기는 이전 페이지가 아니라 이 단계로 복귀)는 `SearchStep`이 렌더링하며, 검색어가 비어 있으면 Popular Spots(노드 `340:4539`, 지역별 칩 — `spot-list-screen.tsx`의 `overflow-x-auto` 필터 칩과 같은 패턴), 검색어가 있으면 자동완성 목록(노드 `340:4584`, 입력한 접두사를 `secondary-300`+semibold로 하이라이트)을 보여줍니다. `create-data.ts`의 `POPULAR_SPOTS`/`searchPlaces`는 지역 검색 API가 없어 Figma 목업("Seong" 검색 예시 + 인기 스팟)을 그대로 흉내 낸 정적 데이터입니다 — 실제 행정동 검색 API가 생기면 `searchPlaces`를 교체하세요.
- `course/course-detail-screen.tsx`(`/course/[id]`, Figma 노드 `358:10841`)는 뒤로가기(`router.back()`) + "Course name" 헤더(코스별 실제 이름을 가져올 API가 없어 Figma의 플레이스홀더 문구를 그대로 씀) + 지도 아이콘(아직 미연결) + 삭제 아이콘 + 세로 점선 타임라인입니다. 삭제 아이콘은 `popoverTarget="delete-course-dialog"`로 확인 다이얼로그(Figma 노드 `384:13130`, "Delete this course? / This action cannot be undone.")를 엽니다 — `my-account-screen.tsx`의 로그아웃 다이얼로그와 같은 네이티브 popover 패턴(`popover="auto"`, `[&::backdrop]:bg-black/30`)입니다. Delete 버튼 색은 `bg-negative`(Figma `state/negative`). 코스 API가 없어 Delete 확정 시 실제 삭제 없이 `router.back()`으로 돌아갑니다 — `push("/course")`가 아닌 이유는 헤더 뒤로가기와 같습니다: History 탭에서 들어왔으면 `/course?tab=history`로, Upcoming에서 들어왔으면 `/course`로, 브라우저 히스토리상 온 곳 그대로 복귀해야 탭이 안 튑니다. 타임라인은 `border-l border-dashed`로 그은 세로선 위에 각 정거장을 `bg-secondary-300` 원형 마커 + `ui/spot-card.tsx`로 배치하고, 점선의 `left` 값은 마커(`size-2.5`)의 실제 중심 x좌표(행의 `pl-[11px]` + 마커 반지름)와 맞춰야 합니다 — 그냥 마커 왼쪽 끝에 맞추면 선이 마커 중심에서 살짝 벗어나 보입니다. 정거장 사이에는 코스 자체의 이동 거리(각 스팟 카드 자신의 `distanceKm`—사용자 현재 위치 기준—와는 다른 값)를 텍스트로 넣습니다. 코스-스팟 연결 API가 없어 `COURSE_STOPS`는 `SPOTS[0]`을 3번 반복하는 정적 스텁입니다 — 실제 코스별 스팟 목록 API가 생기면 `id` 라우트 파라미터로 조회하도록 바꾸세요.
- `ui/text-field.tsx`는 `email-screen.tsx`/`nickname-screen.tsx`/`password-screen.tsx`가 공유하는 인풋 껍데기(label + 인풋 + clear 버튼 또는 비밀번호 표시/숨김 토글 + 캡션)입니다. 값 상태, 검증 로직(정규식, blur 타이밍), 중복 확인처럼 화면마다 다른 것은 각 화면 컴포넌트에 남깁니다. 캡션 한 줄은 `error`(문자열)가 있으면 빨간 테두리+빨간 캡션으로, 없고 `helperText`만 있으면 회색 상시 힌트로 보여줍니다 — 이메일 화면처럼 상시 힌트가 필요 없으면 `helperText`를 안 주면 됩니다. `type="password"`면 clear 버튼 대신 `EyeIcon`/`EyeOffIcon` 표시/숨김 토글을 보여줍니다. `labelVariant="field"`(기본값 `"heading"`)를 주면 라벨이 화면 헤딩(`text-heading-b-18`) 대신 필드 자체 라벨(`text-body-sb-14 text-gray-500`)로 렌더링됩니다 — password-screen처럼 화면 헤딩과 필드 라벨이 따로 있는 경우에 씁니다.
- `code-screen.tsx`의 인증코드 확인은 아직 백엔드 API가 없어 상수(`CORRECT_CODE`)로 흉내만 낸 상태입니다 — 실제 코드 검증/재전송 엔드포인트가 생기면 그걸로 교체하세요. 이전 단계에서 입력한 이메일은 `email-screen.tsx`가 `nextPath`(prop)에 `?email=...`을 붙여 넘기고, `code-screen.tsx`는 `useSearchParams`로 읽습니다 — 화면 간 공유 상태 스토어 없이 라우팅으로만 넘기는 임시 방식입니다. `useSearchParams`를 쓰는 클라이언트 컴포넌트라 `src/app/login/code/page.tsx`/`src/app/login/reset/code/page.tsx`에서 `<Suspense>`로 감싸야 정적 빌드가 됩니다.
- `password-screen.tsx`는 완료 시 `/login`(로그인 메인 화면)으로 이동합니다 — 원래 회원가입 순서(약관 동의 → 이메일 → 코드 → 비밀번호 → 닉네임 → 완료)상 다음은 `/login/nickname`이지만, 현재는 그렇게 연결돼 있지 않습니다. 실제 순서대로 이어붙일 때 `handleNext`를 바꾸세요.
- `email-screen.tsx`/`code-screen.tsx`/`password-screen.tsx`는 회원가입(`/login/email`, `/login/code`, `/login/password`)과 비밀번호 재설정(`/login/reset/email`, `/login/reset/code`, `/login/reset/password`)이 **화면 컴포넌트는 공유하되 라우트는 분리**되어 있습니다. 각 화면은 문구를 URL이나 내부 분기로 알아내지 않고 전부 **props로만** 받습니다 (`headerTitle`, `heading`, `nextPath` 등) — 그래서 화면 컴포넌트 자체는 지금이 가입 플로우인지 재설정 플로우인지 전혀 모릅니다. 어떤 문구를 쓸지/다음에 어디로 갈지는 오직 각 라우트의 `page.tsx`(예: `src/app/login/reset/email/page.tsx`)가 prop으로 정합니다. 나중에 실제 API를 붙일 때도 이 지점(각 `page.tsx`, 또는 거기서 넘기는 `onSubmit` 콜백 prop)에서 가입용/재설정용 엔드포인트를 나눠 부르면 되고, 화면 컴포넌트 안에는 flow 분기를 넣지 마세요. 로그인 메인의 Sign Up은 `/login/terms`를 거쳐 `/login/email`로, Reset Password는 그 약관 단계 없이 바로 `/login/reset/email`로 진입합니다.
- `icons.tsx`는 화면에 속하지 않는 전역 공유 자산이라 하위 폴더로 옮기지 않고 루트에 유지합니다.
- 언어 설정 UI는 화면마다 다릅니다: `login-screen.tsx`는 바텀시트(`ui/bottom-sheet.tsx` 위에 언어 목록을 인라인으로 렌더링, `popoverTarget`으로 트리거)로, `my/language-setting-screen.tsx`(`/my/language`)는 전용 페이지로 엽니다 — Figma에서 두 화면이 실제로 다르게 디자인되어 있어 공용 컴포넌트로 묶지 않았습니다. 둘 다 언어 목록이 정적 배열이라 실제로 언어를 바꾸는 로직은 없습니다(현재 영어 버전만 서비스).

- 하단 탭바는 `ui/tapbar.tsx`에 `active` prop(`"home" | "course" | "my"`)을 받는 공용 컴포넌트로 있습니다 — `home-screen.tsx`, `course-screen.tsx`, `my-screen.tsx`가 같이 씁니다. 세 탭 모두 실제 라우트(`/`, `/course`, `/my`)로 연결되어 있습니다.

### 아이콘 다루기
- 아이콘 라이브러리 의존성(`@iconify/react`, `lucide-react` 등)은 의도적으로 없습니다. 전부 Material Symbols 표준 글리프지만, Next 16 + Turbopack에서 `unplugin-icons` 설정 리스크를 감수하느니 25개를 인라인하는 쪽이 쌉니다. 아이콘이 100개를 넘거나 디자이너가 계속 새로 추가해서 Figma 왕복이 병목이 되면 그때 다시 판단하세요.
- 모든 아이콘은 `fill`/`stroke`가 `currentColor`입니다. 색은 호출부에서 `className`의 `text-*`로 줍니다. 크기도 안 박혀 있으니 `className="size-6"` 식으로 주세요.
- `home`/`map`/`mypage`는 selected 변형이 따로 없습니다 — Figma의 `-selected` 변형이 path가 완전히 동일하고 fill만 달랐습니다. 색으로 구분하세요: `<HomeIcon className={active ? "text-gray-900" : "text-gray-400"} />`
- 반면 `SaveSmIcon`(16px)과 `SaveLgIcon`(24px)은 path가 실제로 다른 별개 도형이라 둘 다 있습니다. `ClockIcon`도 16px 원본입니다. viewBox 확인하고 쓰세요.
- 새 아이콘 추가: Figma MCP `download_assets`로 해당 노드의 SVG를 받으세요. export에는 캔버스 배경(`#F5F5F5` rect)과 아트보드 프레임 path(좌표가 `-277` 같은 음수)가 딸려오니 `<g id="icon/NAME">` 안쪽만 남기고, 레이어 `id`를 지우고, 하드코딩된 색을 `currentColor`로 바꾸고, `fill-rule` 같은 속성을 JSX용 camelCase로 고치세요. 원본 아이콘 이름을 코멘트로 남기세요.
